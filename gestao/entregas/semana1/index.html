    Semana 1 — Setup e Fundação¶

    Concluída

    Período: 12/05/2026 – 18/05/2026

    Objetivo da Sprint¶

    Estabelecer toda a fundação do projeto: repositório, pipeline de CI/CD, ambiente de desenvolvimento containerizado, documentação técnica inicial e definição da equipe.

    Entregas Realizadas¶

    Repositório e Estrutura¶

    • Criação do repositório no GitHub (organização AILAB-MAKERS)
    • Definição da estrutura de pastas (backend/, frontend/, docs/, infra/)
    • Configuração do .gitignore para Java, Node, Python e IDEs
    • Criação do README.md completo com sumário, stack e instruções

    Documentação (MkDocs)¶

    • Setup do MkDocs com Material for MkDocs
    • Configuração do pyproject.toml para gerenciamento com uv
    • CSS customizado com design premium (glassmorphism, animações, dark mode)
    • Deploy automático via GitHub Actions (ci-docs.yml)

    Infraestrutura¶

    • Criação do docker-compose.yml com serviço PostgreSQL
    • Arquivo .env.example com variáveis documentadas
    • Validação do ambiente local com Docker Desktop

    Processo de Desenvolvimento¶

    • Template de Pull Request com checklist de qualidade
    • Definição da convenção de commits (Conventional Commits)
    • Proteção da branch main (merge somente via PR aprovado)
    • Documentação do fluxo de branches (feat/*, fix/*, docs/*)

    Equipe e Funções¶

    • Definição de papéis: 1 Tech Lead + 5 Full Stacks
    • Plano de rotação bimensal entre frentes de trabalho
    • Organização em 3 squads complementares

    Stack Tecnológica¶

    • Seleção e justificativa da stack (Java 17, Spring Boot, PostgreSQL, GCS, Docker)
    • Frontend definido: HTML5, CSS3, JS Vanilla, Bootstrap 5, React
    • Documentação de pré-requisitos para desenvolvimento local

    Resumo Técnico¶

    Métrica Valor
    Commits na semana ~15
    PRs abertos/mergeados 3 / 3
    Páginas de documentação 8
    Containers configurados 1 (PostgreSQL)

    Aprendizados e Decisões¶

    Decisão: MkDocs ao invés de Notion

    A equipe optou por documentação as-code com MkDocs para manter tudo versionado no mesmo repositório do projeto, com deploy automático via GitHub Pages.

    Decisão: uv como gerenciador Python

    Utilizamos uv ao invés de pip para gerenciar dependências Python, garantindo instalação rápida e reprodutível do ambiente de documentação.

    Decisão: Funções genéricas (Full Stack)

    Todos os membros (exceto o Tech Lead) são designados como Full Stack com rotação bimensal entre frentes de trabalho, evitando especialização precoce.
